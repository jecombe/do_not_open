# Blender asset backlog

Rule: build in code first. An asset lands here only when a procedural version cannot
reach the art direction in `docs/DESIGN.md`. Each entry gets a magenta wireframe
placeholder in `packages/scene/src/assets/gltf.ts` (`GLTF_ASSETS`) so the app runs
before the model exists.

## Status

The cats are the first Blender asset. They were procedural until the brief changed:
spheres and cones could carry the traits but not the personality. They are now a
modular kit, generated by script and assembled at runtime from the `CatSpec`.

Everything else (box, tape, label, stamp, depot, broken objects, effects) is still
procedural.

| Candidate            | Decision                                                            |
| -------------------- | ------------------------------------------------------------------- |
| Cats                 | **Done as a Blender kit**, see below                                |
| Torn tape strips     | Closed, stays procedural: the strips fly off and fade in under a second |
| Room props (8 rooms) | **Open, specified in the backlog.** Rooms are a coloured floor and wall |

## The cat kit

```
pnpm assets:cats                       # rebuild everything (about 20 s)
pnpm assets:cats --only tabby,kit      # rebuild some files
```

Needs Blender 5.x on the PATH. Nothing is modelled by hand: `assets/blender/*.py`
describes each shape as a smooth union of a few primitives (a signed-distance field),
meshes it with the OpenVDB that ships inside Blender, and exports glTF. That keeps the
kit reproducible, and it guarantees the two things the renderer needs: closed meshes
and smooth normals, so the inverted-hull outline never tears.

| File          | Role                                                                      |
| ------------- | ------------------------------------------------------------------------- |
| `sdf.py`      | Primitives, lathe and extrude, smooth unions and cuts, colour zones, meshing |
| `cats.py`     | The ten breeds: head, ears, tail and the five posed bodies                |
| `parts.py`    | Face parts (eyes, lids, brows, mouths, whiskers) and the nine accessories |
| `build.py`    | Entry point: builds the Blender objects and exports the files             |
| `preview.py`  | Shows parts in a running Blender (console or Blender MCP) while editing   |

Review with `apps/web/catalog.html` while the dev server runs, for example
`/catalog.html?set=all&size=64` for marketplace-size thumbnails. After a rebuild, the
metadata images have to be rendered again (`pnpm --filter @dno/web render:metadata`).

### cat-<breed>        (ten files: `cat-tabby` ... `cat-glitch`)

```
File:        public/models/cat-<breed>.glb
Dimensions:  a sitting cat is about 0.75 x 1.15 x 0.75
Pivot:       bodies: origin on the floor, +Z forward, +Y up. Head: centre of the skull.
             Ears: base of the ear. Tail: its root, modelled straight along +Y, 0.75 long.
Nodes:       head, ear_L, ear_R, tail, body_sit, body_loaf, body_crouch, body_curl, body_float
Anchors:     empties named <parent>__<anchor>, carrying position, rotation and scale.
             body_*: head, neck, tail. head: eye_L/R, brow_L/R, ear_L/R, whisker_L/R,
             mouth, hat, face.
Poly budget: 35k to 60k triangles per file; one assembled cat is about 30k
Materials:   none. COLOR_0 carries four zone masks instead of a colour:
             R = furSecondary, G = furTertiary, B = furBelly, A = skin, furBase elsewhere.
             Each mask crosses 0.5 on the zone edge; the shader thresholds it per pixel.
Textures:    none
Animations:  none. Breathing, tail, bounce and float are driven by code on the nodes;
             the tail is bent on the CPU along seven joints.
Export:      glTF binary, Draco, +Y up
```

### cat-kit

```
File:        public/models/cat-kit.glb
Pivot:       face parts: origin on the fur, +Z out of the face. Accessories: the origin
             of their anchor (node extra `anchor`: neck, face, eye_R or hat).
Nodes:       eye_ball, eye_iris, eye_pupil, eye_glint, eye_lid, eye_arc, brow,
             mouth_neutral/smile/frown/smirk/open, whiskers_L/R, accessory_<key> x 9.
             For `CatSpec.vice`: prop_joint, prop_smoke (stoned); mouth_wobbly, blush,
             prop_bubble, prop_bottle (drunk).
             Each is an empty with one child mesh per material.
Poly budget: about 100k triangles for the whole file; a face is about 10k
Materials:   flat colours, picked by name at runtime. `main` takes the accessory colour
             of the CatSpec; `fur`, `iris` and `whisker` take the cat's own colours; the
             rest keep their exported colour. A golden accessory replaces all of them.
             Mesh extras: `outline`, `flat` (unlit), `opacity`.
Textures:    none
Animations:  none
Export:      glTF binary, Draco, +Y up
```

Rules for changing the kit:

- Trait keys, rarities and `CatSpec` do not move. The kit changes how a spec is drawn,
  never what it contains.
- A new breed needs a `Breed` entry in `cats.py` and its key in `CAT_BREEDS`
  (`packages/scene/src/assets/gltf.ts`).
- A new accessory needs its pieces in `parts.py` and its anchor in `ACCESSORY_ANCHORS`.
- The Draco decoder served from `apps/web/public/draco/` is a copy of
  `three/examples/jsm/libs/draco/gltf/`. Copy it again when three is upgraded.

## Backlog

One asset set is specified and waiting: the room props. They are scenery behind a
revealed cat, so they must stay quiet: low, flat-coloured, never taller than the cat.

### room-props            (one file, eight named root nodes)

```
File:        public/models/room-props.glb
Nodes:       one root per room key in spec.json: livingRoom, kitchen, bedroom,
             bathroom, attic, serverRoom, laboratory, theVoid
Dimensions:  each set fits a half ring around the origin: inner radius 0.75, outer
             radius 1.3, height at most 0.9 (the cat is about 1.0 tall and sits at the
             origin; the diorama floor is a disc of radius 1.35)
Pivot:       origin at floor level, centre of the disc. Forward +Z (towards the
             camera), up +Y. Keep +Z clear: props go behind and beside the cat.
             Leave (-0.72, 0, 0.28) free, that is where the broken object sits.
Poly budget: 1,500 triangles per room, 12,000 for the file. No LOD.
Materials:   at most 4 per room, flat colours, named <room>_<part>. Take them from
             the room palette in packages/generator/src/catSpec.ts (ROOMS): floor,
             wall, accent. Toon shading and outlines are applied in code.
Textures:    none
Animations:  none. serverRoom may have one looping clip "blink" (2 s) on a named
             emissive node; theVoid may have one looping clip "drift" (6 s)
Export:      glTF binary, Draco compression, +Y up, apply transforms
```

| Room          | Props (two or three, no more)                       |
| ------------- | --------------------------------------------------- |
| `livingRoom`  | sofa arm and cushion, floor lamp, rug edge          |
| `kitchen`     | counter corner with one drawer, stool, hanging pan  |
| `bedroom`     | bed corner with a folded blanket, bedside table     |
| `bathroom`    | bathtub rim, towel rail, bath mat                   |
| `attic`       | two stacked trunks, a roof beam, a bare bulb        |
| `serverRoom`  | one rack with status lights, a cable run            |
| `laboratory`  | bench corner with two flasks, a stool               |
| `theVoid`     | three floating slabs, nothing touching the floor    |

Loading path: add `"room-props"` to `GLTF_ASSETS` with a placeholder, and have
`createDiorama` attach the node named after `spec.room.key`. Until the file exists the
placeholder shows, as the rule at the top of this file requires.

A procedural version is also possible (the broken objects are built that way) and would
keep the repository free of binary assets. The specification above holds either way.

## Spec template

Copy this block per asset.

```
### <asset id>            (must match the key in GLTF_ASSETS)
File:        public/models/<id>.glb
Dimensions:  W x H x D in scene units (1 unit = 1 m; the box is 1.2 x 0.9 x 1.0)
Pivot:       where the origin sits and which way is forward (+Z) and up (+Y)
Poly budget: triangles, per LOD if any
Materials:   count, names, base colours. Flat colours only: toon shading and the
             outline are applied in code. No baked lighting.
Textures:    none unless listed; if any, one atlas, max 1024 px
Animations:  clip names, length, loop or one-shot
Export:      glTF binary, Draco or meshopt compression, +Y up, apply transforms
```
